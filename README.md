# Эмулятор оболочки (вариант 5)

Практическая работа по дисциплине «Конфигурационное управление».
Текущий этап: **3. VFS** (функциональность этапов 1 и 2 сохранена).

## 1. Общее описание

Консольный (CLI) эмулятор оболочки UNIX-подобной ОС, написанный на Python.
Работает в цикле «прочитать строку, выполнить, вывести результат» (REPL).

Реализовано:

- приглашение к вводу `(имя_VFS) username@hostname:~$`: имя пользователя и хоста
  берутся из реальной ОС, имя VFS из параметра `--vfs`;
- парсер с раскрытием переменных окружения (`$HOME`, `${HOME}`), кавычками
  и комментариями;
- сообщения об ошибках (неизвестная команда, неверные аргументы);
- команды `ls` и `cd` (пока заглушки), `exit` и `vfs-save`;
- параметры командной строки: путь к XML-файлу VFS и путь к стартовому скрипту;
- отладочный вывод всех параметров и размера VFS при запуске;
- виртуальная файловая система: загрузка из XML в память, сохранение
  командой `vfs-save` в том же формате;
- стартовый скрипт выполняется как диалог: виден и ввод, и вывод.

Все операции с VFS выполняются в памяти. Исходный XML-файл не изменяется,
данные не распаковываются на диск. Двоичные данные хранятся в формате base64.

## 2. Описание функций и настроек

### Параметры командной строки

| Параметр          | Описание                                              |
|-------------------|-------------------------------------------------------|
| `--vfs ПУТЬ`      | Путь к XML-файлу с содержимым VFS                     |
| `--script ПУТЬ`   | Путь к стартовому скрипту                             |
| `-h`, `--help`    | Справка по параметрам                                 |

Оба параметра необязательны. Без `--vfs` создаётся пустая VFS (один корневой
каталог). Сокращения (`--vf`) не принимаются. Неизвестный параметр или параметр
без значения приводит к подсказке и завершению с кодом 2.

Имя VFS в приглашении это последний элемент пути из `--vfs`
(`vfs_samples/deep_tree.xml` даёт `deep_tree.xml`). Без `--vfs` используется `vfs`.

### Формат VFS (XML)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs>
  <dir name="home">
    <file name="notes.txt">Текст файла</file>
    <file name="logo.bin" encoding="base64">iVBORw0KGgo=</file>
  </dir>
  <dir name="tmp"/>
</vfs>
```

| Элемент / атрибут   | Значение                                                         |
|---------------------|------------------------------------------------------------------|
| `<vfs>`             | Корневой элемент, он же корневой каталог `/`                     |
| `<dir name="...">`  | Каталог, внутри могут быть `<dir>` и `<file>`                    |
| `<file name="...">` | Файл, содержимое это текст элемента                              |
| `encoding="text"`   | Текст в UTF-8 (по умолчанию)                                     |
| `encoding="base64"` | Двоичные данные в base64 (пробелы и переводы строк допускаются)  |

Имя не может быть пустым, содержать `/` или быть `.` и `..`, имена в одном
каталоге не повторяются. Любое нарушение формата приводит к сообщению об ошибке
и завершению с кодом 3.

### Команды

| Команда          | Описание                                                            |
|------------------|---------------------------------------------------------------------|
| `ls [арг...]`    | Заглушка: печатает своё имя и аргументы                             |
| `cd [арг]`       | Заглушка: печатает своё имя и аргументы. Больше одного аргумента: ошибка |
| `vfs-save ПУТЬ`  | Сохраняет VFS из памяти в XML-файл в исходном формате. Нужен один аргумент |
| `exit`           | Завершает работу эмулятора. С аргументами: ошибка                   |

В интерактивном режиме `Ctrl+D` и `Ctrl+C` тоже завершают работу.
Логика `ls` и `cd` появится на этапе 4.

### Разбор строки

- Переменные окружения `$VAR` и `${VAR}` раскрываются до разбиения на слова.
  Неопределённая переменная остаётся в строке без изменений. Пустая переменная
  в начале строки даёт пустую команду, которая игнорируется.
- Слова делятся по пробелам. Слово в двойных или одинарных кавычках может
  содержать пробелы, например `vfs-save "C:\Мои файлы\copy.xml"`.
- Пустые строки и строки, начинающиеся с `#`, игнорируются.

### Стартовый скрипт

Текстовый файл в кодировке UTF-8 (BOM допускается), по одной команде в строке:

- строки выполняются последовательно, на экране видно приглашение, введённая
  строка и вывод, как при ручном вводе;
- пустые строки и комментарии (`#`) пропускаются без вывода;
- ошибочная строка пропускается, печатается `Ошибка (строка N): ...`,
  выполнение продолжается;
- `exit` в скрипте завершает работу эмулятора;
- если скрипт закончился без `exit`, запускается интерактивный режим;
- если файл не найден или не читается, сообщение идёт в stderr, код возврата 1.

### Коды возврата

| Код | Значение                                              |
|-----|-------------------------------------------------------|
| 0   | Нормальное завершение                                 |
| 1   | Не удалось прочитать стартовый скрипт                 |
| 2   | Неверные параметры командной строки                   |
| 3   | Не удалось загрузить VFS (нет файла, неверный формат) |

### Ошибки команд

| Ситуация                         | Сообщение                                             |
|----------------------------------|-------------------------------------------------------|
| Неизвестная команда              | `Ошибка: неизвестная команда 'foo'`                   |
| `cd` с двумя и более аргументами | `Ошибка: cd: слишком много аргументов`                |
| `exit` с аргументами             | `Ошибка: exit: команда не принимает аргументов`       |
| `vfs-save` без пути или с лишним | `Ошибка: vfs-save: требуется один аргумент: путь к файлу` |
| `vfs-save` в недоступное место   | `Ошибка: vfs-save: не удалось сохранить VFS ...`      |

В скрипте к тексту добавляется номер строки: `Ошибка (строка 3): ...`.

## 3. Сборка и запуск тестов

Нужен Python 3.9 или новее. Внешних зависимостей нет, сборка не требуется.

```
make run                                  # интерактивный режим
make run ARGS="--vfs vfs_samples/deep_tree.xml --script startup/stage3_all.emu"
make test                                 # тесты (unittest)
make lint                                 # стиль, нужен flake8
```

Без `make`:

```
python3 src/terminalus.py --vfs vfs_samples/deep_tree.xml
python3 -m unittest discover -s tests -t . -v
```

### Образцы VFS (`vfs_samples/`)

| Файл                   | Что содержит                                                  |
|------------------------|---------------------------------------------------------------|
| `minimal.xml`          | Минимальная VFS: один файл                                    |
| `several_files.xml`    | Несколько файлов в корне: текстовые, пустой, двоичный (base64) |
| `deep_tree.xml`        | Дерево из четырёх уровней каталогов и файлов                  |
| `invalid/*.xml`        | Некорректные файлы: не XML, неверный корень, неизвестный элемент и т. д. |

### Скрипты реальной ОС (`scripts/`)

Для Linux и macOS это `.sh`, для Windows `.bat` (в них включается UTF-8).
Запускать можно из любой папки. Переменная `PYTHON` задаёт интерпретатор
(по умолчанию `python3`, в Windows `python`). Скрипты этапа 3 создают временную
папку, передают её в `EMU_OUT_DIR` для `vfs-save` и удаляют после работы.

| Скрипты (`.sh` и `.bat`)   | Что проверяют                                                        |
|----------------------------|----------------------------------------------------------------------|
| `scripts/run_minimal`      | Все параметры командной строки, `startup/minimal.emu`                |
| `scripts/run_with_errors`  | Все параметры, ошибочные строки скрипта, неверные запуски (коды 1, 2) |
| `scripts/run_all_commands` | Все параметры, `startup/all_commands.emu`, переменные окружения      |
| `scripts/run_vfs_variants` | Три варианта VFS (минимальный, несколько файлов, глубокое дерево)    |
| `scripts/run_vfs_save`     | `vfs-save` на трёх вариантах VFS, копии сравниваются между собой     |
| `scripts/run_vfs_errors`   | Три варианта VFS, некорректные файлы VFS и отсутствующий файл (код 3) |

```
sh scripts/run_vfs_variants.sh
scripts\run_vfs_variants.bat
```

### Стартовые скрипты эмулятора (`startup/`)

| Файл                    | Что содержит                                                        |
|-------------------------|---------------------------------------------------------------------|
| `stage3_all.emu`        | Все команды этапов 1–3, режимы `vfs-save`, обработка ошибок         |
| `minimal.emu`, `with_errors.emu`, `all_commands.emu` | Скрипты этапа 2                         |
| `save_copy1.emu`, `save_copy2.emu` | Вспомогательные для круговой проверки `vfs-save`        |

## 4. Примеры использования

Запуск `startup/stage3_all.emu` на дереве `deep_tree.xml`
(`student@pc` это пользователь и хост реальной ОС, папка сохранения `/tmp/out`):

```

[отладка] VFS в памяти: каталогов 11, файлов 9

(deep_tree.xml) student@pc:~$ ls
[заглушка] команда: ls
[заглушка] аргументы: []
(deep_tree.xml) student@pc:~$ ls -l /
[заглушка] команда: ls

(deep_tree.xml) student@pc:~$ cd /
```
